| `/tmp/aaris-unity-batch/scene-readback.json` | Unity AssetDatabase scene load confirmation | **Deleted on STOP** | Generated by Unity Editor |

| GitHub Actions 1-day JPEG artifact | AI visual review, **not** a Library backup | Expires after 1 day | No commits to game LFS |

Why `/tmp`? The original Codespace's 32-GiB persistent disk had about
**0.35 GiB** free at verification. The **separate** /tmp filesystem had
~94 GiB free. Keeping a full import and Unity temporary caches on /tmp
avoids filling the original game disk **during this session**, but
**/tmp is cleared whenever Codespace stops**. There is no cheap
transparent symlink trick that turns /tmp into persistent storage.

Source: https://docs.github.com/en/codespaces/developing-in-a-codespace/persisting-environment-variables-and-temporary-files

## How AI operates the same Codespace without phone or terminal

The owner-only GitHub Actions workflow is
`.github/workflows/ai-codespace-on-demand.yml`.
It listens for **one newly committed** JSON file on branch
`ai/codespace-jobs`, under `.aaris/jobs/<unique-id>.json`, from owner
Aaris-khan-don. It uses the configured `AARIS_CODESPACE_TOKEN` secret
to wake the **same named Codespace** when stopped, connect through
reviewed SSH, run exactly one allowlisted operation, and return
`AARIS_RESULT_JSON` in Actions logs. Do not print access tokens.

Example single operation (AI commits JSON with GitHub connector):

```json
{"id":"unity-recover-example-001","operation":"unity_session_recover","args":[]}
```

**Do not commit that example ID again**; generate a new unique valid
job ID for every operation. One job at a time—wait for Actions to finish
before adding the next, to prevent canceled/overlapping work.

| AI intent | Owner-only operation | What it does |
| --- | --- | --- |
| Determine real current state | `unity_session_status` | Read-only project hash, PID, disk and scene |
| Rehearse lost /tmp | `unity_session_stop_simulation` | Read-only hypothetical STOP, DOES NOT kill process |
| Remember scene and location | `unity_session_checkpoint` | Write one small manifest under /workspaces |
| Recover after stop/next AI visit | `unity_session_recover` | Reuse live Editor, reopen compatible scratch, OR recreate missing scratch/import safely |
| Track Unity import | `unity_virtual_gui_status` | Editor PID, log, scene readback, remaining disk |
| Read area in Unity | `unity_virtual_live` with `inspect` JSON | Nearby trees/terrain and native IDs |
| Edit a tree (only scratch!) | `unity_virtual_live` with `move_tree` or `scale_tree` | Guard exact ID + expected position; save and independently inspect |
| Render photo | `unity_virtual_live` with `capture`, then `unity_virtual_frame` | Store JPEG as private expiring Actions artifact |
| Compare scratch and original | `unity_scratch_reconcile` | SHA-256 read-only comparison including `.meta` |

For `unity_virtual_live` put exactly ONE short JSON string in
`args[0]`; refer to `Docs/UNITY_AI_NO_VNC_VERIFIED_20261105.md` for
validated examples. Avoid duplicate edits when a response is
`pending:true`. Poll using `unity_virtual_result` with the original
job ID. The Editor's C# bridge runs in the scratch copy and has an
isolated command root; the original Editor does not consume these jobs.

## After a Codespace restart (the exact decision tree)

1. The next AI commits `unity_session_status` or directly
   `unity_session_recover` (GitHub Actions wakes the named Codespace).
2. Read previous checkpoint, verify original core fingerprints and
   Editor executable. **If source changed since checkpoint, stop
   and review**. Do not silently revert user edits.
3. If real Unity PID still running on this exact scratch project,
   reuse it. Never open a duplicate process.
4. If scratch survives but the process is stopped, start the
   licensed **normal graphical Editor** on hidden Xvfb `:12` and
   reuse its existing imported Library.
5. If /tmp was cleared: copy original Assets/Packages/ProjectSettings
   to **a new isolated scratch** with read-only original input, patch
   only the *scratch* AI bridge command root, then restart normal Unity
   Editor and reimport Library. **Do NOT use headless batch mode**.
6. Check the generated scene readback before reporting success.
   Once loaded, inspect the saved camera target and let AI restore
   its viewing focus. Do NOT replay past move/scale commands.
7. Save a new persistent checkpoint only after successful scene
   readback. Reimport may be lengthy; no ETA or exact-resume guarantee.
8. Do not promote scratch-changed `.asset`, `.unity`, `.prefab`,
   `.mat` or `.meta` to original without explicit, separately
   validated conflict-safe Git LFS change management.

**A stopped Codespace is not running an agent.** The current recovery
is triggered when the next authorized AI Actions job starts the
Codespace; merely reopening the Codespaces web UI does not automatically
send that job. A devcontainer `postStartCommand` could be used in
a **future separately reviewed** configuration, but applying it to
the existing dirty Codespace would require configuration migration
and could impact the current Unity install. Do not rebuild just to
claim automatic restart.

## Durable cache solution (not yet installed)

To eliminate the required fresh import after STOP, obtain sufficient
**persistent** disk and move/rebuild the entire Unity project+Library
there, or use a trusted authenticated remote Library cache with
immutable hash validation and a supported restore process.

GitHub supports changing an existing Codespace machine to an available
type with larger storage. **This can increase usage charges and stops
the running Codespace**, so AI must not change machine size without
the owner's explicit approval and a verified backup of 36 or more
dirty/untracked paths. Official documentation:
https://docs.github.com/en/codespaces/customizing-your-codespace/changing-the-machine-type-for-your-codespace

**Never** rely on a symlink to /tmp for persistent Editor/Library,
make a second global Git LFS download of already present 764/764
assets, delete original `Library`, or assume a JSON checkpoint is
a backup of binary assets or imported cache.
